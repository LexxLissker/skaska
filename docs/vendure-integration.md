# Подключение Vendure

Storefront остаётся независимым от схемы Vendure: он получает небольшой нормализованный каталог и не хранит фото в браузере.

## Товары и фото

- Создайте коллекции: `pelmeni`, `vareniki`, `manty`, `hinkali`, `kotlety`, `golubtsy`, `lapsha`.
- Для каждого веса создайте отдельный вариант товара, например «500 г» и «1 кг». Тогда остатки и цена каждого веса будут честно учитываться Vendure.
- Загружайте изображения в Vendure Admin и указывайте их как `featuredAsset` товара. Storefront отображает это поле. Клик по карточке не открывает загрузку файла.

## Настройки среды

В `.env.local` укажите публичный Shop API:

```dotenv
NEXT_PUBLIC_VENDURE_API_URL=https://api.example.ru/shop-api
NEXT_PUBLIC_VENDURE_CUSTOM_OPTIONS=false
```

Если Next и Vendure работают под одним доменом, лучше проксировать `/shop-api` на Vendure и использовать `NEXT_PUBLIC_VENDURE_API_URL=/shop-api`. Тогда сессия активной корзины сохранится без отдельной настройки cookie между поддоменами.

## Конструктор товара

Когда готовы хранить выбор теста и начинки в заказе, добавьте custom fields в конфигурацию Vendure:

```ts
customFields: {
  OrderLine: [
    { name: "dough", type: "string", nullable: true },
    { name: "fat", type: "string", nullable: true },
    { name: "doughColor", type: "string", nullable: true },
    { name: "meatTexture", type: "string", nullable: true },
  ],
}
```

После миграции схемы поставьте `NEXT_PUBLIC_VENDURE_CUSTOM_OPTIONS=true`. До этого флаг должен оставаться `false`: продукт всё равно добавится в активную корзину, но без параметров, а запрос не будет зависеть от ещё не созданных полей.

## Доставка и оплата

Их не стоит рассчитывать в браузере. Следующий серверный слой — плагин Vendure с собственными сущностями для зон, графика доставок и слотов. Он должен записывать в заказ выбранные дату, слот, зону, цену доставки и определять доступные методы оплаты. После подключения конкретного эквайринга кнопка «Оплатить» будет переводить заказ в оплату через штатный payment flow Vendure.
